## 三、已落实的产品定义

**定位**：只读本地、不联网、不要账号的私人唱片库 —— 首页页脚、设置页、隐私说明三处都写死这句话，
且 `module.json5` 里**没有** `ohos.permission.INTERNET`（可被审核与用户直接验证）。

**视觉**：近黑 `#0B0B0D` + 铜金 `#C8A96A` + 纸白 `#FBF9F6`；唯一高饱和色来自封套；
无圆角卡片堆叠、无渐变按钮、无 Material 蓝；三套主题（暗夜/白纸/磁带）全部落到 `Theme.ets` 的令牌表。

**P0 六件事**：目录授权入库 · 真后台播放 · 音频焦点 DUCK · 队列/歌单/收藏/最近 · 歌词与服务卡片 · 首启引导与空态。

**明确不做**：在线音源、社交、推荐流、会员订阅、账号体系。代码里也没有对应入口。

## 四、关键实现选择（以及为什么）

1. **首页是"按专辑聚合的封套墙"，不是歌曲列表。**
   5000 首按歌曲铺会变成一片重复封面；按专辑聚合后，`GROUP BY album` 一条 SQL 就能出墙，且更像唱片店。
2. **没有封面就程序化生成封套，不摆灰块。**
   本地曲库封面覆盖率极低，灰块会把整面墙变成"未加载"；散列取色的封套纯本地绘制，不联网、不占存储。
3. **示例数据进同一张表，用 `source` 隔离。**
   空库时用户连播放器都验收不了；示例与真实数据同库同查询，切来源只换条件，不复制第二套代码。
4. **示例曲目走计时器引擎，真实曲目走 AVPlayer。**
   示例没有真实音频文件，但仍要能验收播放/暂停/进度/上下曲/模式；`PlayerCore` 按 uri 前缀分流。
5. **`PlayerCore` 是唯一状态源，UI 只收快照。**
   迷你条、播放页、播控中心三处必须一致；页面各自读内核字段一定会出现"切 tab 后进度停了"。
6. **错误自动跳下一首，连挂 3 首才停。**
   一个坏文件不该让整个播放停住；但也不能无限跳过，否则用户看到的是"歌在乱跳"。

  无词时推空行清掉残留。内核自己拉词（`loadLrcForSession`），后台自动切歌也不断粮。
